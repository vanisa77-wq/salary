# 月中到職／離職 破月薪資、勞健保、勞退計算規格
> 給 Claude Code 的實作說明（薪資計算器 index.html 新功能）
> 依據:民法第 123 條、勞基法第 22 條、勞工保險條例第 11 條、全民健康保險法第 30 條、勞動部說明

---

## 核心原則(四行看懂)

| 項目 | 計算方式 | 天數基礎 |
|------|---------|---------|
| 破月薪資 | **日薪 = 月薪 ÷ 30**,乘以在職日曆天數(累加法) | 一律 30 天;做到二月底者補 1~2 天 |
| 健保 NHI | **整月計收,不按比例** | 以「月」為單位 |
| 勞保 | **按在職天數比例** prorate /proʊˈreɪt/ = 按比例 | 一律 30 天(不分大小月、二月) |
| 勞退 | **按在職天數比例** | 一律 30 天(二月月底有特例) |

⚠️ 注意:**薪資天數**和**勞保天數**在二月會不一樣!薪資對員工有利要補天數,勞保按實際日期。兩套天數必須分開計算,不可共用同一個變數。

## 0. 破月薪資(不足月薪水)

### 0-1 基本規則
- 未特別約定時,依民法第 123 條:**日薪 = 月薪 ÷ 30**,不分大小月。
- 在職天數 = **日曆天** calendar days /ˈkæləndɚ deɪz/,**含例假日、休息日**(不是只算上班日!)。
- 必須用「**加項計算**」(數在職天數),不可用「扣除法」(30 − 不在職天數),扣除法在大月會少給,違反勞基法第 22 條全額給付,罰 2~100 萬。
  - 例:月薪 30,000,1/16 離職。加項:16 天 = 16,000 ✓;扣除法:30 − 15 = 15 天 = 15,000 ✗ 少給。

### 0-2 二月特例(只有「做到二月最後一天」的人才補天)
二月只有 28 或 29 天,但月薪是以 30 天計,少掉的 1~2 個「虛擬日」掛在**二月底之後**(想像成 2/29、2/30)。因此:
- **在職到二月最後一天的人**(含全月在職、二月中到職做到月底)→ 在職天數 **+2**(28 天二月)或 **+1**(閏年 29 天二月)
- **二月中就離職的人** → 不補天,按實際在職日曆天計算(累加法)

例(月薪 30,000,非閏年):
- 2/21 到職做到月底 → (8 + 2) × 1,000 = **10,000**
- 2/10 離職 → 10 × 1,000 = **10,000**(不補天)
- 全月在職 → 28 + 2 = 30 天 = 整月薪 ✓

一致性驗證:2/10 離職的人(10 天)+ 2/11 接任做到月底的人(18 + 2 = 20 天)= 剛好 30 天,同一個職位當月薪資總額不會超過一個月。

📌 可選政策(目前**不採用**):部分 HR 實務會對二月中離職者也加計 1~2 天以避免爭議(多給合法)。若日後 Vanisa77 決定採用,只需把公式中的 `febBonus` 條件從「做到月底」放寬為「二月一律補」,並同步更新使用說明書。

### 0-3 統一公式(建議實作方式)
上面所有規則可以濃縮成一條公式,對任何月份都成立:

```javascript
// 破月薪資計費天數
// hireDay: 本月到職日(月初已在職傳 1)
// leaveDay: 本月離職日(做到月底傳當月最後一天)
// daysInMonth: 當月實際天數(28/29/30/31)
function salaryDays(hireDay, leaveDay, daysInMonth) {
  const worked = leaveDay - hireDay + 1;          // 在職日曆天(累加法)
  const febBonus = (leaveDay === daysInMonth)      // 只有在職到月底才補天
    ? Math.max(0, 30 - daysInMonth)                // 二月 +1~2,大小月 +0
    : 0;
  return Math.min(30, worked + febBonus);          // 上限 30(大月做滿=整月薪)
}

// 破月薪資 = Math.round(月薪 / 30 * salaryDays(...))
```

驗證:
- 1/16 離職(31 天月):16 天 ✓
- 2/10 離職(28 天月):10 天 ✓(不補天,符合表格)
- 2/21 到職做到月底:8 + 2 = **10** ✓(符合表格「建議」欄)
- 3/21 到職做到月底:11 + 0 = **11** ✓(符合表格)
- 12/30 離職(大月):30 天 = 整月薪 ✓
- 2/1 做滿全月:28 + 2 = 30 = 整月薪 ✓
- 5/31 到職做到月底:min(30, 1 + 0) = 1 ✓

### 0-4 尾數處理
日薪除不盡時(例:月薪 32,000 ÷ 30 = 1,066.67),建議**最後才四捨五入**:`Math.round(月薪 ÷ 30 × 天數)`,不要先把日薪四捨五入再乘天數,誤差會放大。

## 1. 健保(不需要按天數計算)

- 健保以「月」為單位,由該員工**當月最後一天**的投保單位負責。
- **月中到職**:不論幾號到職,只要做到月底,公司收「整月」健保費。
- **月中離職**:公司**不收**當月健保費(由下一個投保單位負責,如新公司、區公所)。
  - 例外:員工在**當月最後一天**離職 → 公司仍收整月健保費。

```
if (離職日 === null || 離職日 === 當月最後一天) {
  健保 = 整月保費;
} else {
  健保 = 0;  // 月中離職,本單位不收
}
```

⚠️ 與現有邏輯的整合:本系統健保採「次月依實際帳單遞延收取」,此規則影響的是**帳單上會不會出現該員工**,計算器只需在到職/離職當月正確判斷收或不收整月。

## 2. 勞保(按比例,一律以 30 天為基礎)

### 2-1 月中到職(做到月底)
```
天數 = 30 - 到職日 + 1
```
- 大月(31 天)在 **30 號或 31 號**到職 → 天數一律算 **1 天**。
  - 即:`天數 = Math.max(1, 30 - 到職日 + 1)`

### 2-2 月中離職(月初就在職)
```
天數 = min(離職日, 30)
```
- 7/31 離職 → 30 天(大月上限 30)。
- 2/28 離職 → 28 天(二月按實際日期)。

### 2-3 同月到職又離職
```
天數 = min(離職日, 30) - 到職日 + 1
```
官方範例驗證:
- 1/5 到職、1/20 離職 → 20 − 5 + 1 = **16 天**
- 3/20 到職、3/31 離職 → 30 − 20 + 1 = **11 天**
- 2/18 到職、2/28 離職 → 28 − 18 + 1 = **11 天**
- 5/30 到職、5/31 離職 → 30 − 30 + 1 = **1 天**

### 2-4 保費計算
```
不足月勞保費(員工自付) = Math.round(月投保級距對應之員工自付額 × 天數 / 30)
```
※ 尾數處理(rounding /ˈraʊndɪŋ/ = 四捨五入)請比照勞保局帳單:**先算完再四捨五入到元(`Math.round`),不可無條件捨去(`Math.floor`)**。實作後需用一期實際帳單核對。

> **修正紀錄(115.7.24)**:index.html 的破月勞保費計算誤用 `Math.floor`(無條件捨去),導致與勞保局「勞工保險普通事故及就業保險合計之保險費分擔金額表」及實際勞保名冊金額不符。範例:張婉君 115 年 5 月到職,投保薪資 36,300(自付額 908 元/月),在職 18 天 → 908 × 18 / 30 = 544.8,原程式捨去為 544 元,官方表格與名冊皆為 **545 元**。已改為 `Math.round`,與官方表格一致。

## 3. 勞退(規則與勞保相同,二月有一個特例)

### 3-1 月中到職
```
天數 = 30 - 到職日 + 1
```
例:2/2 到職 → 30 − 2 + 1 = 29 天。

### 3-2 月中離職
```
天數 = min(離職日, 30)
```
例:2/2 離職 → 2 − 1 + 1 = 2 天。

### 3-3 同月到職又離職
```
天數 = min(離職日, 30) - 到職日 + 1
```
**二月特例**:若做到二月最後一天(28 或 29 日),視同做到「第 30 天」:
- 2/1 到職、2/28 離職 → 計 **30 天**(整月)
- 2/2 到職、2/28 離職 → 30 − 2 + 1 = **29 天**

```
if (月份 === 2 && 離職日 === 二月最後一天) {
  天數 = 30 - 到職日 + 1;   // 視同做滿到第30天
} else {
  天數 = min(離職日, 30) - 到職日 + 1;
}
```

## 4. 建議實作(JavaScript)

```javascript
// 統一函式:回傳勞保/勞退計費天數(以30天為基礎)
// hireDay: 當月到職日(月初已在職傳 1)
// leaveDay: 當月離職日(做到月底傳 null)
// month, year: 用於判斷二月與當月最後一天(民國年請先轉西元)
function insuredDays(hireDay, leaveDay, month, year, type /* 'labor' | 'pension' */) {
  const lastDayOfMonth = new Date(year, month, 0).getDate(); // 28/29/30/31
  const start = hireDay ?? 1;
  let end;

  if (leaveDay == null) {
    end = 30; // 做到月底,以30天計
  } else if (type === 'pension' && month === 2 && leaveDay === lastDayOfMonth) {
    end = 30; // 勞退二月特例:做到二月底視同第30天
  } else {
    end = Math.min(leaveDay, 30); // 大月31號 → 30
  }

  return Math.max(1, end - start + 1); // 大月30/31號到職至少算1天
}

// 健保:整月或不收
function nhiFullMonth(leaveDay, month, year) {
  const lastDayOfMonth = new Date(year, month, 0).getDate();
  return (leaveDay == null || leaveDay === lastDayOfMonth);
}
```

- 案例 13:30,000 ÷ 30 × 11 = **11,000**(勞動部函釋案例:大月到職按累加法算日曆天,不可用扣減法只給10天)

- 案例 15:30,000 ÷ 30 × 10 = **10,000**

※ 注意三套天數的差異(薪資 ≠ 勞保的情況):
- **大月且做到 31 日**(案例 7、13):薪資按日曆天數(31 日要給薪),勞保封頂 30 天 → 薪資比勞保多 1 天。
- **二月做到月底**(案例 8、9、10):薪資補 1~2 天,勞保按實際日期不補 → 薪資比勞保多 2 天(勞退在同月加退保做到二月底時也視同 30 天,見案例 9、10)。
- **二月中離職**(案例 12、15):薪資不補天 = 勞保天數,**兩者相同**。
- 小月(30 天):三套天數永遠一致。

## 6. UI 規格(配合現有「基本薪資設定」介面)

### 6-0 核心需求(最重要,先看這裡)
當月有到職或離職時,使用者**只填到職日/離職日**,系統必須**自動分別算出各套天數**,並各自套用到對應的計算,不共用、不需手動換算:

```
輸入:到職日 及/或 離職日(單一資料來源)
        │
        ├→ 薪資天數 salaryDays()   → 自動套用:本薪 ÷ 30 × 薪資天數
        ├→ 勞保天數 insuredDays(labor)   → 自動套用:勞保費 × 勞保天數/30
        ├→ 勞退天數 insuredDays(pension) → 自動套用:勞退提繳 × 勞退天數/30
        └→ 健保判斷 nhiFullMonth() → 自動套用:收整月 或 不收
```

禁止的做法:讓使用者手動填一個天數、四項計算共用同一個數字——大月和二月時薪資與勞保天數本來就會不同(見第 5 章案例 7、8、13),共用必定算錯其中一項。

### 6-1 輸入欄位
- 現有的「本月為離職月」勾選框與「離職日」date picker /deɪt ˈpɪkɚ/ = 日期選擇器 保留。
- 比照離職月的做法,新增「**本月為到職月**」勾選框,勾選後展開「**到職日**」date picker。
- 兩者可同時勾選(同月到職又離職的情況)。
- 驗證:到職日/離職日必須落在「計算年月」的月份內(注意民國年轉西元:115 年 = 2026 年),不符時紅字提醒。

### 6-2 「實際在職天數」欄位降級為顯示用
- 有填到職日/離職日時,此欄位**變成唯讀的自動顯示**(顯示薪資天數),不再是計算的資料來源——所有計算一律從日期推導,避免手動填的數字被四項計算共用。
- 沒填日期時(全月在職)維持現狀:留空 = 整月出勤。
- 若確有特殊約定需要覆寫,提供「進階:手動覆寫天數」的展開選項,覆寫時必須分別覆寫薪資/勞保/勞退三個天數,並顯示 ⚠️ 警示。

### 6-3 破月天數自動計算卡(核心新功能)
只要有填到職日或離職日,就在欄位下方顯示一張唯讀計算卡,**三套天數分開列**,並直接代入該員工的實際數字:

```
📊 破月自動計算(115年6月,當月共30天)
────────────────────────────────
薪資天數   26 天  → 本薪 33,200 ÷ 30 × 26 = 28,773 元
勞保天數   26 天  → 勞保費按 26/30 比例計收
勞退天數   26 天  → 雇主提繳按 26/30 比例
健保      不收   → 月中離職,由下一投保單位收取
────────────────────────────────
✓ 本月薪資天數與勞保天數相同
```

- 當薪資天數 ≠ 勞保天數時(大月做到31日、二月做到月底),最後一行改為橘色警示並說明原因,例如:
  `⚠️ 薪資 11 天、勞保 10 天不同:大月到職,薪資算日曆天(31日要給薪),勞保以30天為基礎`
- 全勤獎金列:離職/到職月依第 7 章確認後的規則顯示(未定義前先顯示「請確認全勤規則」提醒)。

### 6-4 展開式規則說明(防健忘設計)
在計算卡下方放一個可收合的說明區,用原生 `<details><summary>` 實作(不需額外 JS):

```html
<details class="rule-help">
  <summary>📖 展開看「為什麼是這個天數」— 計算規則與範例</summary>
  <!-- 內容依當月情境動態顯示對應的規則段落 -->
</details>
```

展開後的內容要**動態代入當前員工的情境**,而不是死板的通用說明。依情境顯示對應段落:

| 當月情境 | 展開顯示的說明 |
|---------|--------------|
| 小月到/離職 | 「日薪 = 月薪÷30,實際在職幾天算幾天。例:陳郁婕 6/26 離職 → 在職 26 天,薪資與勞保都是 26 天」 |
| 大月做到 31 日 | 「薪資算日曆天(31日是真實出勤日),勞保封頂 30 天,兩者差 1 天。例:3/21 到職 → 薪資 11 天、勞保 10 天」 |
| 二月中到職做到月底 | 「二月視為 30 天,補足虛擬的 2/29、2/30 → 在職天數+2。例:2/21 到職 → 薪資 (8+2)=10 天」 |
| 二月中離職 | 「離職採累加法不補天,實際在職幾天算幾天。例:2/10 離職 → 10 天」 |
| 同月到職又離職 | 「薪資算日曆天;勞保 = min(退保日,30) − 加保日 + 1。例:3/20~3/31 → 薪資 12 天、勞保 11 天」 |

說明區底部固定放兩行法規提醒:
- 勞保**到職當日**即須加保,離職**當日**辦退保(假日可延至下一上班日,退保日回填離職當天),不可提早退保。
- 一日工資本系統採「一律以 30 日推計」(未事先約定之法定預設,勞委會 102 年函釋)。

### 6-5 與現有功能的整合
- 勾選「本月為離職月」時既有的特休未休折算、健保退保說明照舊,計算卡的健保列與退保說明要一致,不要出現兩處講法不同。
- LINE 報表解析器(parser /ˈpɑrsɚ/)不變:到職日/離職日屬於例外情況,由 Vanisa77 手動填,不需要老師回報。
- localStorage 員工資料庫可新增選填欄位「到職日」,到職當月自動偵測並提示勾選「本月為到職月」。

## 7. 其他薪資項目的破月處理

- **全勤獎金(已決定 ✅ 115.7.7)**:破月月份按比例發 → `破月全勤 = Math.round(全勤獎金 × 薪資天數 ÷ 30)`(例:800 元、在職 26 天 → 693 元)。與現有請假規則的疊加順序:先算破月全勤,再套用既有規則——在職期間請**整天事假** → 該月全勤歸零;請**時數事假** → 破月全勤 − (全勤獎金 ÷ 8 × 小時),下限 0 元。此規則需同步寫入使用說明書,並一體適用於所有員工。
- **固定/不固定津貼(已決定 ✅ 115.7.7)**:津貼性質各有不同,破月月份**不自動按比例**,金額由 Vanisa77 逐項自行決定填入。系統輔助:破月月份在津貼欄位旁顯示灰色參考值 `參考:按比例 ÷30 為 X 元`,方便需要時直接採用,但不強制、不自動帶入。
- **值班費、加班費**:按實際發生計算,不受破月影響(維持現狀)。

## 8. 追溯調整項改版(獨立需求,與破月功能同批實作)

現況:追溯調整區只支援健保、原因選「其他」時無法填寫內容、要填「投保級距」編號。改版如下:

### 8-1 每筆調整項的欄位
```
[方向] [險種] [原因] [(其他時)自填說明] [月份] [投保金額] [金額] [×刪除]
```

- **方向**:補扣(進應扣區)/ 沖退(退還員工)——維持現有設計。
- **險種**:下拉選「健保 / 勞保」(新增勞保)。若日後有員工勞退自提 6%,再加「勞退自提」選項,目前不做。
- **原因**:依險種顯示不同的預設選項 + 「其他」:
  - 健保:健保署追溯補收 / 眷屬異動追溯 / 投保金額調整沖退 / 其他
  - 勞保:勞保局勾稽補收 / 投保薪資調整追溯補收 / 投保薪資調整沖退 / 加退保日期更正 / 其他
- **其他自填說明**:原因選「其他」時展開文字輸入框,**必填**(不填不能新增該筆),字數上限 50 字。
- **月份**:被追溯的月份(民國年月)。
- **投保金額**:改為填投保金額(如 34,800),**不再填級距編號**。輸入時提供級距表金額的自動完成(datalist /ˈdeɪtəlɪst/ = 自動完成清單);金額不在官方級距表時顯示 ⚠️ 提醒但仍允許(因應舊表或特殊核定)。系統內部自行以金額對照級距,使用者不接觸編號。
- **金額**:系統依投保金額 × 險種自動帶出建議值,**允許手動覆寫**——實務上以健保署/勞保局核定通知上的實際數字為準,通知金額與系統試算不同時,填通知的數字。

### 8-2 顯示與列印
- 維持「逐筆列示、不壓成淨額」原則(每筆獨立顯示在應扣區或應發區)。
- 薪資單上每筆調整顯示:險種 + 原因(含自填內容)+ 月份,讓老師看得懂為什麼多扣或退錢,例如:`勞保 補扣|勞保局勾稽補收 115年5月 +120 元`。
- 「清空本次補收/特殊設定」按鈕要一併清掉所有調整項(維持現有換人前清空的習慣)。

### 8-3 舊資料相容
localStorage 中既有的健保調整紀錄(存級距編號的)載入時自動轉成對應投保金額顯示;轉不出來的顯示原始值 + ⚠️ 請人工確認。

## 9. 本次實作必須一併處理的三條規則(容易被遺漏)

### 9-1 破月月份的投保級距仍按「約定月薪」申報與計費
月中到職/離職者當月實領薪資雖然較少,但**投保級距不因此降級**——勞健保投保薪資依「約定月薪總額」對應級距(例:約定月薪 33,200 + 經常性津貼 → 對應 34,800 級距),再按天數比例算保費。系統禁止用「當月實領金額」去反查級距。

### 9-2 破月月份如又有請假,扣款基準一致
破月月份內若再有事假/病假,日薪扣款基準同樣是「月薪 ÷ 30」(與破月計薪同一套邏輯,函釋要求加項與減項計算內涵一致)。計算順序:先算破月薪資天數 → 再扣請假 → 全勤獎金依第 7 章確認後的規則處理。

### 9-3 雇主負擔也要按同一套天數比例
如果系統或年度 Excel 有計算雇主成本(勞保雇主 70%、健保雇主 60%、勞退 6%、職災保險),破月月份**雇主負擔用和員工自付相同的天數比例**(勞保/勞退按各自天數,健保整月或不收)。不可員工按比例、雇主卻算整月。
※ 另注意:勞退月提繳分級表與勞保級距表是**兩張不同的表**(勞退上限較高、級距較多),目前系統勞健保共用同一級距欄位,實作時確認勞退對照的是勞退專用表。
