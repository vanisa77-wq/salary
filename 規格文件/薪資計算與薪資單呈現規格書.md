## 一、核心資料結構

每位員工每月的薪資資料應包含以下欄位:

```javascript
const employee = {
  name: "",              // 員工姓名
  yearMonth: "115/06",   // 薪資月份(民國年/月)
  baseSalary: 33200,     // 月薪制底薪
  attendanceBonus: 800,  // 全勤獎金(定額)
  otherPayItems: [],     // 其他應領項目,如 { name: "學習檔案製作費", amount: 200 }
  insuranceGrade: 34800, // 投保級距(勞健保同級距,由工資總額對照級距表)
  dependents: 3,         // 健保依附眷屬人數(輸入可超過3,計算時上限3)
  workDays: 30,          // 當月在職天數(整月=30,月中離職=實際天數)
  isResignMonth: false,  // 是否為離職月
  resignDate: null,      // 離職日(離職月必填)
  personalLeaveDays: 0,  // 一般事假日數(整日)
  personalLeaveHours: 0, // 一般事假時數(小於1日者)
  sickLeaveDays: 0,      // 普通傷病假日數(整日)
  sickLeaveHours: 0,     // 普通傷病假時數(小於1日者)
  otherLeaveNote: "",    // 其他假別手動備註(如「家庭照顧假1日」「產假 6/1–7/26」),僅顯示於備註,不進計算
  attendanceBonusOverride: null, // 全勤手動覆寫金額(null=依公式自動算;其他假別需調整時由管理者手動輸入)
  overrideReason: "",    // 覆寫理由(覆寫時必填,顯示於薪資單)
  leaveDates: [],        // 請假日期清單(顯示於備註)
  unusedAnnualLeave: 0,  // 特休未休日數(僅離職月使用,預設0=已休畢)
  annualLeaveTotal: 0,   // 當年度特休總天數(離職月必填,供備註「特休X日已休畢」使用)
  adjustments: [],       // 追溯調整項,見第五節
  payDate: "",           // 發薪日期
  accountLast4: ""       // 匯入帳號末四碼
};
```

## 二、計算公式(依序執行)

### 2.1 日薪

```
日薪 = baseSalary / 30
```

- **不預先四捨五入**,保留小數(如 33200/30 = 1106.6667)參與後續計算。
- 顯示時可顯示至小數 2 位(1,106.67),或顯示原始算式。

### 2.2 在職底薪(月中離職按比例)

```
在職底薪 = baseSalary × workDays / 30
```

- 整月在職:直接等於 baseSalary,**不要顯示「日薪 × 30」的拼湊公式**。
- 離職月:結果為加項,採 `Math.round`(四捨五入)。
- ⚠️ 禁止「先把日薪四捨五入成整數再乘天數」——這會產生公式與金額對不上的問題
  (例:1,107 × 26 = 28,782 ≠ 28,773)。一律用原式 `baseSalary × workDays / 30` 一次算完再捨入。

### 2.3 全勤獎金(115/1/1 新制,重要:邏輯全面改寫)

> 法源:《勞工請假規則》115/1/1 修正施行(勞動部 114/12/9 公告)。
> ① 普通傷病假之全勤獎金扣發,**應按請假日數依比例計算**,不得全數不發;
>    以小時請假者,每小時扣發上限 = 全勤獎金 ÷ 30 ÷ 8。超扣違反勞基法第 43 條(罰 2 萬–100 萬)。
> ② **家庭照顧事假**與婚假、喪假、公假、公傷病假、產假、陪產假、生理假等法定保障假別,
>    **不得視為缺勤**,一律不影響全勤獎金。
> ③ 一般事假不在保障範圍,中心既有規則(整日事假全勤歸零、時數事假按 800÷8×小時扣)仍合法沿用。

```
// 第一步:基準金額(離職/到職破月先按比例)
基準全勤 = isResignMonth ? roundPay(attendanceBonus × workDays / 30) : attendanceBonus;

// 第二步:一般事假(中心規則,維持不變)
if (personalLeaveDays >= 1) {
  全勤獎金 = 0;   // 整日事假 → 全勤歸零
} else {
  事假扣減 = roundDeduct(attendanceBonus / 8 × personalLeaveHours);   // 時數事假

  // 第三步:普通傷病假 → 只能按比例扣(新制)
  病假扣減 = roundDeduct(attendanceBonus / 30 × sickLeaveDays
                       + attendanceBonus / 30 / 8 × sickLeaveHours);

  全勤獎金 = Math.max(0, 基準全勤 − 事假扣減 − 病假扣減);
}

// 第四步:手動覆寫(其他假別由管理者自行判斷後輸入)
if (attendanceBonusOverride !== null) {
  全勤獎金 = attendanceBonusOverride;   // overrideReason 必填,顯示於薪資單
}
```

**其他假別採手動處理**(中心實務以事、病假為大宗,其餘偶發):
管理者於 `otherLeaveNote` 填寫假別與日期,必要時以 `attendanceBonusOverride` 覆寫全勤。
手動輸入時對照下表,**保障假別一律不得扣全勤**:

| 假別 | 全勤 | 工資 |
|---|---|---|
| 家庭照顧事假(115新制) | 不得扣 | 不支薪(比照事假,可小時請) |
| 婚假、喪假、公假、公傷病假 | 不得扣 | 照給 |
| 產假(任職滿6個月) | 不得扣 | 照給 |
| 陪產檢及陪產假 | 不得扣 | 照給 |
| 生理假(每月1日,年3日內不併病假) | 不得扣 | 半薪 |
| 育嬰留職停薪 | 期間不發薪,以破月邏輯計算在職天數 | 停薪 |

- 育嬰留停月份:比照月中到職/離職規格以 workDays 計算在職底薪;
  留停期間勞健保續保與遞延繳納屬特殊作業,保費金額由管理者依公文手動輸入。

- **絕對禁止**「加項 +800、扣項 −800」的加了又扣寫法;扣減在加項內部完成,
  扣項區**永遠不得出現**任何「全勤」相關項目。
- **絕對禁止**病假(不論幾日)使全勤直接歸零——那是 115 年前的舊制,現已違法。
- 扣減方向不利於勞工 → 一律 `roundDeduct`(捨去);基準全勤為發給 → `roundPay`。
- 顯示範例:
  - `全勤獎金:+747(本月病假2日,依比例扣發 800÷30×2 = 53)`
  - `全勤獎金:+0(本月事假1日,依本中心工作規則不符全勤)`
  - 覆寫時:`全勤獎金:+800(手動調整:家庭照顧假1日,依勞工請假規則不視為缺勤)`
- 備註區病假月固定加註:`全勤獎金依勞工請假規則115年新制按病假日數比例扣發`。
- ⚠️ 病假「半薪扣款」(2.7)之日薪基準本中心採 baseSalary÷30(未含全勤),
  扣款額低於函釋上限(底薪＋實領全勤)÷30 之半數,屬優於法令,**維持現制不改**。

### 2.4 勞保自付額

```
整月:勞保自付 = 查表值(依 insuranceGrade 對照勞保普通事故費率員工自付額)
離職月:勞保自付 = Math.floor(整月勞保自付 × workDays / 30)   // 按日計收,扣項捨去
```

- 顯示格式:`勞保自付(級距 34,800):−870`
- 離職月顯示:`勞保自付(級距 34,800,按日計收 870 × 26/30):−754`
- **禁止**只寫「整月固定」這種無依據的說明文字。

### 2.5 健保自付額

```
每口自付 = Math.round(insuranceGrade × 0.0517 × 0.30)
計收眷屬 = Math.min(dependents, 3)    // 眷屬計收上限 3 口
本人健保 = 每口自付
眷屬健保 = 每口自付 × 計收眷屬
```

- **必須拆成兩行顯示**,不得合併為「4口×540」:
  ```
  健保自付(本人):−540
  健保自付(眷屬 3 口):−1,620
  ```
- 若 dependents > 3,備註加註:`實際依附${dependents}口,依法以3口計收`。
- **離職月(月中退保)**:本人與眷屬健保均為 0,顯示:
  ```
  健保自付:0(6/26退保,當月保費依規定由轉入單位計收)
  ```
  禁止寫「最後在職月不收」這種易誤導的說法。

### 2.6 事假扣款(不支薪,全額扣)

```
事假扣款 = Math.floor(日薪 × personalLeaveDays)
```

- 例:1106.6667 × 2 = 2213.33 → **扣 2,213**(捨去)。
- 顯示:`事假扣款(6/10、6/15,共2日):−2,213`,請假日期必列。

### 2.7 病假扣款(半薪,扣一半)

```
病假扣款 = Math.floor(日薪 × 0.5 × sickLeaveDays)
```

- 例:1106.6667 × 0.5 × 1 = 553.33 → **扣 553**(捨去)。
- 顯示:`病假扣款(6/20,1日半薪):−553`。

### 2.8 特休未休折算(僅離職月;預設隱藏邏輯)

> 中心管理常態為員工於離職前休畢特休,故本欄位**預設 0、預設隱藏**;
> 但欄位與計算邏輯必須保留(勞基法第 38 條為強制規定,不得刪除)。

```
if (!isResignMonth) {
  // 非離職月:折算行與相關備註皆不出現
} else if (unusedAnnualLeave === 0) {
  // 已休畢(常態):應領項目「不顯示」折算行
  // 備註「自動加註」:`特休${annualLeaveTotal}日已休畢,無未休折算`
} else {
  // 例外(有未休):顯示折算行
  特休折算 = roundPay(日薪 × unusedAnnualLeave);   // 加項,四捨五入
  // 顯示:`特休未休折算(3日 × 1,106.67):+3,320`
}
```

- `annualLeaveTotal`(當年度特休天數)於離職月為必填,供備註引用——
  同時作為結算時「確認該員工今年特休天數」的強制查核點。
- 已休畢時的備註句**不可省略**(寫明零比沉默安全,為日後申訴之防禦證據)。
- 依據:勞基法第 38 條,離職結算之強制規定,不得以約定排除。

### 2.9 合計

```
應領小計 = 在職底薪 + 全勤獎金 + 其他加項 + 特休折算 + 調整項(退還方向)
應扣小計 = 勞保 + 健保本人 + 健保眷屬 + 事假 + 病假 + 調整項(補扣方向)
實領金額 = 應領小計 − 應扣小計
```

## 三、捨入規則(全域規則,最重要)

> **黃金原則:捨入方向永遠朝有利於勞工的方向。**

| 項目性質 | 捨入函式 | 說明 |
|---|---|---|
| **加項(發給員工的錢)** | `Math.round()` | 四捨五入(或 `Math.ceil` 進位,擇一全域統一) |
| **扣項(從薪資扣的錢)** | `Math.floor()` | **無條件捨去**,絕不進位 |
| 中間計算值(日薪、比例) | 不捨入 | 保留浮點數至最終金額才捨入 |
| 勞健保查表值 | 不再捨入 | 依政府公告表列金額 |

實作要求:

```javascript
// 建立統一的捨入工具函式,全程式禁止直接呼叫 Math.round/floor 處理金額
function roundPay(amount)    { return Math.round(amount); }  // 加項專用
function roundDeduct(amount) { return Math.floor(amount); }  // 扣項專用
```

- **禁止**同一份程式對不同員工出現不同捨入結果(如某人事假扣 1,107、另一人扣 2,213 這種進位/捨去混用)。
- **禁止**先捨入中間值再運算(如日薪先進位成 1,107 再乘天數)。

### 4.2 離職月版面(增列項目)

- 表頭加一行:`在職期間:115/6/1 – 6/26(6/26 退保離職)`
- 加項必含:`特休未休折算`(即使 0 也要在備註交代)
- 健保行改為退保說明(見 2.5)
- 備註加:`特休結算依勞基法第38條;自請離職,無資遣費事項`(或依實際離職性質)

### 4.3 版面通則

1. **禁用 emoji**(移除 💰 等所有表情符號)——正式文件規範。
2. 每一筆金額**必須附依據或計算式**,且公式必須能驗算回金額本身:
   - 好:`33,200 × 26/30 = 28,773`
   - 壞:`1,107 × 26`(算出來是 28,782,對不上)
3. 級距、請假日期、眷屬口數、法規條號,是四種必須出現的「可驗算錨點」。
4. 零元項目:有意義的零(全勤不符、健保退保、特休休畢)**保留並註明原因**;
   無意義的零(如 `0 × 30/30`)整行隱藏。
5. 名詞使用正式全名:「學檔」→「學習檔案製作費」;「事假底薪」→「事假扣款」;
   刪除「全薪」「整月固定」等易誤讀字眼。
6. 表尾固定三要素:發薪日期、匯入帳號末四碼、法規備註。
7. 眷屬只顯示**人數**,不顯示姓名與關係(個資保護)。

### 4.4 設計樣式(沿用既有標準)

- 背景:霧感粉灰(Morandi)色系,禁止深色背景
- 字型:微軟正黑體,禁止斜體
- 字級:標題 16–18px、內文 15px、備註 13px、輸入欄 15px(手機友善)
- 文字顏色:#1a1a1a 或 #333,禁止淺灰
- 版面緊湊,不留過多空白

## 五、追溯調整項功能(新增功能)

### 5.1 需求背景

健保署勾稽補收、級距追溯調整等情形,會產生跨月的補扣/退還。
**禁止把多筆調整壓成一個淨額**(如「−-29」這種雙重負號),必須逐筆列示。

### 5.2 資料結構

```javascript
const adjustment = {
  direction: "deduct" | "refund",   // 補扣 → 進扣項;退還 → 進加項
  reason: "健保署追溯補收" | "級距調整沖退" | "眷屬異動" | "其他",
  targetMonth: "115/04",            // 所屬月份(不是本月)
  grade: 36300,                     // 該筆適用的級距(用當時的級距,不是現在的)
  amount: 563,
  note: ""                          // 自動生成備註,可手動補充
};
```

### 5.3 顯示規則

- `refund` 顯示於**應領項目**:
  `健保溢扣退還(5月眷屬1口,級距38,200):+592`
- `deduct` 顯示於**應扣項目**:
  `健保補扣(4月眷屬新增1口,級距36,300):−563`
- 每筆必標:所屬月份 + 事由 + 適用級距。
- 依 reason 自動生成備註句型,例如選「健保署追溯補收」時:
  `備註:健保補扣XXX元係依健保署核定通知,補收眷屬(X)115/X月保險費`
  ——標明「依健保署核定通知」以釐清責任歸屬。

## 六、驗證用測試案例(實作完成後必須全數通過)

### 案例 A:整月在職 + 事假 1 日(對應員工:林小樂型)

輸入:底薪 33,200、全勤 800、級距 34,800、眷屬 3、事假 1 日

| 項目 | 期望值 | 驗算 |
|---|---|---|
| 在職底薪 | +33,200 | 月薪制整月 |
| 全勤獎金 | +0 | 事假1日不符全勤,扣項區不得出現全勤 |
| 勞保自付 | −870 | 級距34,800查表 |
| 健保本人 | −540 | round(34800×0.0517×0.30) |
| 健保眷屬 | −1,620 | 540×3 |
| 事假扣款 | **−1,106** | floor(33200/30×1) = floor(1106.67),不是1,107 |
| **實領** | **29,064** | 33,200−4,136 |

### 案例 B:離職月(對應員工:陳大國型)

共同輸入:底薪 33,200、全勤 800、級距 34,800、在職 26 天(6/26 離職)、
病假 1 日、事假 2 日、annualLeaveTotal = 7

| 項目 | 期望值 | 驗算 |
|---|---|---|
| 在職底薪 | +28,773 | round(33200×26/30)=round(28773.33) |
